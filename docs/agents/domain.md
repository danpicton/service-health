# Domain docs

This is a single-context repo. Use a root `GLOSSARY.md` and system-wide ADRs in `docs/adr/`.

Before exploring an area, read the root glossary and relevant ADRs if they exist. Proceed without comment if they do not exist; create them when terms or decisions need recording.

Use the glossary's defined terms in issues, code proposals, and tests. If a needed concept is absent, reconsider the term or record the gap for `domain-modeling`.

If proposed work conflicts with an ADR, identify the conflict explicitly rather than silently replacing the decision.
